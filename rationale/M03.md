# M03 rationale

I support our choice to run the model on the laptop and to use Azure only to store each recording with its
metadata and to show it on a dashboard. Every recording is saved on the laptop first and uploaded after, so if
the classroom Wi-Fi fails we lose nothing and upload it later. The model also runs with the same Python code
we use for training, so it sees the signal in the same way both times. In Azure each recording becomes one row
of metadata in a table, a bit like a patient file, and we can delete it everywhere with one command if the person
asks. My doubt: the free dashboard plan sleeps when nobody uses it, so we must open it before the demo.

Source: Microsoft Learn. What is Azure Table storage? 2024.
https://learn.microsoft.com/en-us/azure/storage/tables/table-storage-overview
